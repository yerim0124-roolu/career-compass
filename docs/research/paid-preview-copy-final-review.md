# 유료 미리보기(심층 분석 미리보기) 카피 최종 검수

- 날짜: 2026-07-14
- 범위: `src/components/paid/PaidPreviewView.tsx`의 표시 카피 전체 + 표시 전용 테스트. 결제·유료 문항·결과 생성·파이프라인 무변경.

## 1. 기존 문구 문제

`PaidPreviewView.tsx`가 상단 소개를 **명사구 조합 템플릿**으로 만들고 있었다:
- `'${primary}'와 '${secondary}' 사이에서 흔들리고 있어요. 이 마음의 정체와, … 구체적으로 짚어드릴게요.`
- primary/secondary는 `subtypeToKorean`이 반환하는 30+개 명사구(예: "또렷하지 않은 내 강점", "끌리는 일을 부를 이름", "선택지를 닫기 어려운 마음", "끝나지 않는 정보 탐색" …).

각 명사구는 자연스러워도 **두 개를 따옴표로 묶어 '사이에서 흔들리고'로 연결**하면 조합이 어색해지는 경우가 많았다(문학적 은유 "마음의 정체" + 조합 불안정). 리포트 항목도 은유·괄호·'진단'·'1분'·'3갈래' 등 추상/부자연 표현이 있었다.

## 2. 최종 상단 소개 문장 (개인화 → 안전한 단일 기본 문장)

**결정: 명사구 조합 개인화를 제거하고 모든 사용자에게 단일 기본 문장을 사용.**

> 지금은 내가 잘하는 것과 해보고 싶은 일이 아직 하나의 방향으로 연결되지 않았어요. 심층 분석에서는 결정을 막는 이유를 정리하고, 현실적으로 가능한 선택지와 이번 달 바로 시작할 30일 실험을 제안해드려요.

- "당신" 반복·따옴표 개념어·문학적 은유("마음의 정체"·"줄다리기"·"부를 이름")·"흔들리고 있어요"·"구체적으로 짚어드릴게요" 제거.
- 지금 무엇이 막혀 있는지(방향 미연결) + 심층 분석이 주는 실제 가치(원인 정리·현실 선택지·30일 실험)만 설명. 결과 보장·심리 진단 어투 없음.

### 개인화 vs 단일 기본 문장 비교 (§7)

`subtypeToKorean` 명사구를 profile/subtype별로 조합하면 아래처럼 8개 대표 사례 모두에서 조합 불안정이 발생한다. 완성 문장 템플릿을 8+종 유지하는 것보다, **단일 기본 문장이 8개 사례 모두에 자연스럽게 적용**되므로 단일 문장을 채택했다(과도한 개인화가 오히려 어색 → 안전한 단일 문장).

| 조건/profile | 기존 조합 예시(어색) | 단일 기본 문장 적용 |
|---|---|---|
| 방향 불명확(lowOptionVisibility) | "'또렷하지 않은 내 강점'과 '끌리는 일을 부를 이름' 사이에서 흔들리고 있어요" | 자연스러움(방향 미연결을 그대로 설명) |
| 선택지 너무 많음(scatteredExplorer) | "'선택지를 닫기 어려운 마음'과 '끝나지 않는 정보 탐색' 사이에서…" | 자연스러움 |
| 현실 조건 큼(realityLocked) | "'움직일 재정 여유'와 '감당할 수 있는 시도 크기' 사이에서…" | 자연스러움("현실적으로 가능한 선택지" 문구가 오히려 부합) |
| 자신감 부족(unvalidatedAspirant) | "'시장의 반응'과 '해낼 수 있을지에 대한 확신' 사이에서…" | 자연스러움 |
| 손실 회피(conflictedAtFork) | "'생활에 줄 영향'과 '쌓아온 걸 이어갈 길' 사이에서…" | 자연스러움("결정을 막는 이유" 부합) |
| 정체성 전환(identityTransition) | "'새로운 나로 옮겨가는 일'…" | 자연스러움 |
| category_only(구체 미확정) | 명사구 FALLBACK 조합 → 모호 | 자연스러움(구체 유형 불필요) |
| fallback(신호 부족) | primary=secondary → "…을 두고 고민" 변형 | 자연스러움 |

→ 상단 문장은 **profile에 따라 달라지지 않는 정적 단일 문장**으로 구현(개인화 미사용). 조합 어색 위험 0.
