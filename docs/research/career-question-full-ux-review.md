| pt_delay | (없음) | 방금 고른 결과물을 아직 시작하지 못했다면, 가장 큰 이유는 무엇인가요? | (없음) |

- 세 or_* 문항의 **선택지 5종은 문구까지 동일하게 유지**(같은 척도 비교 설계가 화면에서 명확). 각 문항의 옵션 ID·scoreEffects·constructEffects·응답 저장·엔진 매핑 불변.
- 소라벨은 `QuestionStep.comparisonLabel`(신규 optional, **표시 전용**) 필드로 구현. 스코어링·엔진은 이 필드를 읽지 않으며, `ChatLikeFlow`가 질문 위에 렌더한다.

### 5.2 or_* 비교 세트의 실제 화면 구조

- 질문 말풍선 상단에 보라색 소캡션 **"가능성 비교 · 1/3 → 2/3 → 3/3"**가 뜨고, 그 아래 방향별로 **첫 문장이 뚜렷이 다른 질문**(콘텐츠로 풀어내기 / 직접 사업·프로젝트 / 조직 안 역할 확장)이 온다. 세 문항 모두 동일한 5개 느낌 선택지(에너지 생김 / 의미 있지만 돈 걱정 / 돈은 되지만 피곤 / 잘하지만 설레지 않음 / 아직 모르겠다)를 그대로 제시해, "같은 척도로 세 방향을 비교"한다는 설계가 화면만으로 드러난다.
- 1/3 화면에만 "세 가지 방향을 같은 기준으로 빠르게 비교해볼게요." 안내를 둬, 세트의 시작임을 알린다.
- 결과: 6→7→8이 '같은 질문 반복'이 아니라 '1/3→2/3→3/3 비교 과정'으로 읽힘(브라우저 확인).

### 5.3 pt_delay — 실행 중 사용자용 선택지 존재 여부

- 질문을 직전 ap_experiment('방금 고른 결과물')에 앵커링해 cs_blocker(결정 장애물)와의 반복감을 제거.
- **"이미 작게 시작했고 진행 중"** → `pt_delay_acting`('이미 작게 해보고 있다')로 **존재**. 실행 중 사용자는 이 옵션으로 답할 수 있어 조건형 질문("아직 시작하지 못했다면")에 갇히지 않음.
- **"특별히 미루고 있지 않음(순수 미해당)"** → 정확히 대응하는 옵션은 **없음**. 이번 단계에서는 임의로 옵션을 추가하지 않았다(엔진/선택지 불변 원칙). 대다수 실행 중 사용자는 `pt_delay_acting`으로 자연 귀결되나, "시작도 안 했지만 딱히 막힌 것도 없다"는 소수 상태를 담는 중립 옵션은 부재.
  - **별도 결정 사항(후속)**: pt_delay에 중립/미해당 옵션(예: 'pt_delay_none — 특별히 막고 있는 건 없다') 추가 여부. 추가 시 biasPatternEngine의 pt_delay 매핑(무코드 처리)만 검토하면 되며, 이번 작업 범위 밖으로 남긴다.

### 5.4 브라우저 반복감 재평가

새 순서로 3→9, 19→21 구간을 직접 진행하며 재확인(콘솔 오류 0, 데스크톱·모바일):

- **ar_roles(3) → rc_options(4) → ar_narrow(5)**: 자연스럽게 연결됨. ar_narrow가 중립 리드 + "방향 없어도 됨" 안내로 바뀌어, 앞서 '선택지 거의 없음'을 고른 사용자도 전제 충돌 없이 답할 수 있음(이전 (e) 항목 해소).
- **or_content/venture/internal(6~8)**: 소라벨 1/3·2/3·3/3 + 방향별 상이한 첫 문장으로 **'반복'이 아니라 '의도된 비교'로 읽힘**. High 반복감 → **Low~Medium으로 완화**(동일 선택지는 '같은 척도'로 납득됨). 3연속 자체의 물리적 길이는 남으므로, 더 줄이려면 §2-①의 MERGE_UI(한 화면 묶음)가 다음 후보.
- **모바일**: 소라벨(11px 소캡션) + 2줄 질문 + 안내 2줄이 375px에서 오버플로우 없이 정상. 선택지도 각 1줄.
- **cs_blocker(19) → ap_experiment(20) → pt_delay(21)**: pt_delay가 '방금 고른 결과물'을 명시해, cs_blocker의 '결정을 미루게 만드는 것'과 **다른 질문으로 분명히 구분**됨. 앞 문항 반복이 아니라 '그 행동을 아직 못 한 이유'로 읽힘(이전 ⑤·(e) 항목 해소).
